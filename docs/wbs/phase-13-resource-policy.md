### P13-05: Routing Service — Resource Validation ([#399](https://github.com/deghosal-2026/mcp-fabric/issues/399))

**Description:** Add resource validation to the capability request pipeline: extract resources from params (via dimension_value_map), merge pack + identity bindings, pass to OPA, handle violations.

**Dependencies:** P13-02, P13-03, P3-04 (routing service)
**Effort:** 8h

**Checklist:**
- [ ] Add `resolve_resources(capability, params, identity)` to RoutingService
  - Query declared dimensions for the capability
  - For each dimension, attempt extraction via param_path or fall back to agent-provided `resources` field
  - Return `{dim_key: value}` dict
- [ ] Add `merge_bindings(identity_id, pack_id)` to resolve effective allowed resources
  - Query identity bindings + pack bindings
  - For each dimension, compute intersection of identity and pack values
  - Return `{dim_key: [allowed_values]}`
- [ ] Extend `execute()` to pass `identity_resources` and `request_resources` to OPA
- [ ] Handle resource violation: return 403 with violation details
- [ ] Handle missing dimension values: return 400 `missing_resource_dimension`
- [ ] Log resource check result in audit event details JSONB
- [ ] Extend batch request processing to include per-request resource validation
- [ ] Add latency tracking for resource resolution (new histogram bucket)

**Success Criteria:**
- Resources are extracted and validated in every capability request for dimension-constrained capabilities
- Missing required dimensions return 400 with dimension key in error details
- Violations return 403 with `resource_not_allowed` code and violation detail
- Resource resolution adds < 5ms p95 to routing overhead
- At least 8 integration tests covering all paths
